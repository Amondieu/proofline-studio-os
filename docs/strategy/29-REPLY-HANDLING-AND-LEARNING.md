# 29 — Reply handling and learning

## Reply classifications

Classify each outcome once, then record a human-owned next action:

`positive · question · meeting · negative · opt_out · bounce · no_response · other`

An opt-out immediately sets suppression and prevents further messages. A reply
classification does not automatically change a client project or offer.

## Outcome fields

- prospect ID and source sequence;
- received timestamp;
- classification;
- minimal factual summary;
- next action and owner;
- suppression state;
- human reviewer where needed;
- link to the original approved draft and audit.

Do not copy full inbox content into the repository. Keep only the minimum
operational record and a controlled external reference where appropriate.

## Learning loop

Review after each small wave:

1. Did the source and trigger remain relevant?
2. Did the prospect understand the audit without correction?
3. Which objections repeated?
4. Were opt-outs or bounces clustered by source or message?
5. Did the archetype hypothesis survive the reply?
6. Which single variable should be changed next?

Track delivery, positive replies, negative replies, opt-outs, bounces, booked
calls, qualified calls, and source quality. Do not treat reply rate alone as a
conversion result.

## Controlled experiment rule

Change one variable per wave: ICP, current trigger, subject, CTA, or teardown
format. Record hypothesis, cohort boundary, dates, and stop rule. Promote a
pattern into the cookbook only after human review and enough local evidence; an
outbound result never becomes universal proof.

## Pilot boundary

The first 20-company exercise is research-only until every send gate is
reviewed. This repository change creates the workflow and records, not a live
prospect list or an outbound campaign.
