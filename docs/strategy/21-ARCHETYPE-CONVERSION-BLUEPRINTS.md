# 21 — Archetype conversion blueprints

These cards are starting systems, not plug-and-play page templates. Each must
be adapted to the client’s real offer, proof, audience, and constraints.

## 01 — AI / Automation Authority System

- **Job:** Make a costly workflow and the technical mechanism credible enough to
  earn a qualified assessment conversation.
- **Buyer hesitation:** “Will this work with our systems, and will it create
  operational risk?”
- **Primary conversion:** Request a workflow assessment.
- **Secondary conversion:** Download a capability brief.
- **Hero:** Name the expensive workflow, show the mechanism, make the first
  diagnostic step concrete.
- **Proof:** Documented method, relevant technical example, named constraints,
  client-approved evidence.
- **Sequence:** Outcome-first hero → workflow diagnosis → mechanism → proof or
  concept boundary → engagement path → objections → assessment CTA.
- **Direction:** Precision System.
- **Motion:** Restrained signal motion that explains a system; no animated
  dashboard as proof.
- **Prohibited:** AI hype, fabricated savings, generic robot imagery, jargon
  without translation, autoplay background video.
- **Offer:** Authority Landing Sprint.
- **KPI:** Qualified assessment requests.

## 02 — SaaS Launch & Demand System

- **Job:** Turn a product use case into a clear launch-ready buying path.
- **Buyer hesitation:** “Is this for a real use case, and is switching worth it?”
- **Primary conversion:** Book a product demo.
- **Secondary conversion:** Start a guided trial.
- **Hero:** Lead with use case and outcome; let product evidence earn feature
  detail.
- **Proof:** Product walkthrough, use-case evidence, security or implementation
  facts where relevant, permissioned customer proof.
- **Sequence:** Use-case hero → problem cost → mechanism → workflow demo → fit
  or comparison → proof → FAQ → demo or trial CTA.
- **Direction:** Cinematic Authority.
- **Motion:** Stage a real product flow only when the reduced-motion and
  performance paths remain intact.
- **Prohibited:** Feature wall above the fold, fake UI, unbounded pricing
  claims, motion before message.
- **Offer:** Launch System.
- **KPI:** Qualified demo or trial starts.

## 03 — Expert Authority System

- **Job:** Make a point of view, fit, and engagement path legible.
- **Buyer hesitation:** “Will this expertise be practical for my situation?”
- **Primary conversion:** Apply for a fit call.
- **Secondary conversion:** Read a point-of-view note.
- **Hero:** Point of view first; biography and credentials support the decision.
- **Proof:** Named perspective, relevant experience, permissioned case evidence,
  clear scope boundaries.
- **Sequence:** Point-of-view hero → who it is for → method → selected proof →
  engagement model → about → fit questions → application CTA.
- **Direction:** Editorial Luxury.
- **Motion:** Quiet transitions and typographic emphasis.
- **Prohibited:** Credential dump, vague transformation language, manufactured
  scarcity, unconsented testimonials.
- **Offer:** Authority Landing Sprint.
- **KPI:** Qualified fit-call applications.

## 04 — Creative Portfolio & Inquiry System

- **Job:** Curate relevant proof and attract better-fit briefs.
- **Buyer hesitation:** “Can this studio handle our kind of brief within our
  constraints?”
- **Primary conversion:** Send a project brief.
- **Secondary conversion:** View selected work.
- **Hero:** Curated point of view and a small set of relevant work, not an
  unstructured archive.
- **Proof:** Rights-cleared work, project context, role clarity, permitted
  collaborator credits.
- **Sequence:** Point-of-view hero → selected work → case context → capabilities
  → process → fit and constraints → inquiry CTA → rights and credits.
- **Direction:** Cinematic Authority.
- **Motion:** Scroll choreography only when it clarifies the work; preserve still
  and readable mobile alternatives.
- **Prohibited:** Unlicensed work, masonry overload, hover-only meaning, autoplay
  sound, context-free case studies.
- **Offer:** Launch System.
- **KPI:** Qualified project inquiries.

## 05 — High-Trust Lead Engine

- **Job:** Reduce uncertainty before a sensitive inquiry.
- **Buyer hesitation:** “Can I trust this provider, and what happens to my
  information?”
- **Primary conversion:** Request a confidential consultation.
- **Secondary conversion:** Ask a question.
- **Hero:** Make safety, scope, response expectations, human contact, and the
  privacy boundary visible before asking for sensitive information.
- **Proof:** Verified credentials, process transparency, privacy and consent
  text, permissioned evidence.
- **Sequence:** Trust-first hero → situation fit → what happens next → proof and
  credentials → privacy boundary → FAQ → contact route → legal layer.
- **Direction:** Editorial Luxury.
- **Motion:** Minimal motion; focus order, consent, and calm interaction win.
- **Prohibited:** Fear-based urgency, dark-pattern consent, unverified badges,
  sensitive data before purpose is clear, regulated guarantees.
- **Offer:** Authority Landing Sprint.
- **KPI:** Qualified, consented inquiries.

## QA handoff

The selected blueprint adds context to the existing Build and QA receipts. It
does not relax them. Every blueprint still passes accessibility, form, legal,
ownership, rollback, performance, and human launch review.
