# Proofline Studio Constitution

## Purpose

Proofline is a human-governed website and landing-page studio. Agents may
research, propose, structure, implement, test, and block. Humans decide source
promotion, client claims, rights, legal text, design direction, and launch.

## Working principles

### I. Think before coding

State assumptions, surface ambiguity, identify the smallest useful scope, and
push back when a simpler path is available. Never convert an unresolved
assumption into a client fact or a launch decision.

### II. Simplicity first

Use the minimum code, schema, and process that solves the stated problem. Do
not add speculative providers, abstractions for one use, autonomous agents, or
error paths for impossible states.

### III. Surgical changes

Every changed line must trace to the request or its acceptance criteria. Match
the existing repository style, preserve unrelated work, and document adjacent
dead code rather than deleting it opportunistically.

### IV. Goal-driven execution

Translate the request into observable acceptance criteria. Prefer a failing
test, contract fixture, or reproducible check before implementation when
practical. Converge by running the checks and recording the evidence.

## Required feature artifacts

Every non-trivial change has a specification, plan, task list, and convergence
record under `specs/`. Research changes also record source quality, limitations,
and reuse decisions.

## Authority and safety

Automated checks can block and explain; they cannot approve or launch. No agent
invents proof, testimonials, metrics, legal text, rights, or consent. A visual
reference, award, forum consensus, or model output is never proof by itself.
