# WITHKODEX portfolio vertical slice roadmap

Branch: `feat/withkodex-portfolio-v1`

## Dependency order

1. `100-withkodex-portfolio-master-site-v1` — parent shell and route contract.
2. `110-proofline-route-v1` — capability-line message and quality system.
3. `120-ai-automation-authority-v1` — first archetype proof-of-method page.
4. `130-teardown-interest-intake-v1` — minimal, non-sending CTA path.

No child feature may silently expand the parent scope. Each feature converges
against its own requirements before implementation proceeds.

## Seven working slices

1. **Scope:** review Constitution, source boundaries, route map, and unknowns.
2. **Research/spec:** run the LLMArena planning prompt and preserve only
   reviewable artifacts.
3. **Message:** approve Proofline and archetype message maps, CTA, claims, and
   concept boundary.
4. **Direction:** compare Precision, Cinematic, and Editorial; select one by
   human gate.
5. **Creative concepts:** if useful, generate text-only Higgsfield candidates;
   do not upload client/confidential material and do not approve an asset yet.
6. **Tasks:** turn approved plans into atomic implementation tasks with test and
   evidence outputs.
7. **Skeleton:** implement routes, tokens, semantic states, and automated QA;
   keep form non-sending and production launch blocked.

## Go / no-go for archetype activation

The archetype remains concept-only until the spec is approved, the quality
profile and anti-pattern review pass, the Studio Concept disclosure is visible,
claims have evidence or qualification, asset provenance is approved, mobile/
keyboard/contrast/motion checks pass, the form is privacy-reviewed or disabled,
legal/privacy routes exist, the launch receipt is complete, and a human signs
the launch review.
