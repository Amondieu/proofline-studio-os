# Plan — WITHKODEX portfolio master site V1

Use a portable route/content shell that keeps semantic copy, tokens, asset
records, and provider prompts separate. The existing Proofline master site is a
reference/proof surface; this feature defines the future vertical slice and
does not rewrite the external parent site.

## Implementation order

1. Route/content manifest and parent capability source register.
2. Shared semantic shell, navigation, footer, and status disclosure.
3. Token layer with Precision as default and other directions deferred.
4. Proofline and archetype content assembled from approved message maps.
5. Interest-only teardown state machine with no provider by default.
6. Legal/privacy placeholders and data-flow documentation.
7. QA receipts, link checks, mobile/keyboard review, provenance review, and
   human gate record.

No slice includes deployment, DNS, credentials, tracking activation, or a
claim that external WITHKODEX routes already exist.
